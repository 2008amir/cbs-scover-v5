# Architecture
- This repository runs a standalone Node.js Baileys bot; V1 and V2 share one WhatsApp socket.
- index.js owns the only bot process; evaluated V1 source must never spawn index.js again. Let the hosting panel restart processes, honor stop signals, and log numerical host resource diagnostics to distinguish external kills from socket failures.
- Keep shared prefix and automation aliases in lib/env-config.js backed by lib/database/settings.json; V2 must not overwrite V1 settings on import, so commands stay consistent across engines and restarts.
- Remove exact V1 spellings from V2 handler.command arrays without deleting plugin files; discover routing/menu ownership from actual V1 handlers, not a static denylist, to preserve unique V2 aliases.
- Wire V2 events once per socket and let V1 own shared automation events in merged mode, preventing duplicate status receipts and reactions.
- Keep prefix parsing, command recognition and bounded account+message-ID dispatch claims (never chat/sender addressing, since WhatsApp redelivers one message under phone-number and LID addresses) in lib/v2/index.js; derive V1 command names only from the main command switch, excluding inner option switches and loader-disabled cases; all generic reactions defer prefixed input to the registered-command handler, and chatbot side listeners only archive so each command has one execution owner.
- lib/fonts.js owns transforms and per-account activation in shared settings; attach once, preserve commands/URLs/mentions/code, edit only recent fromMe text, and resolve styled previews through its registry. Suppress successful plugin logs, retain failures.
- Keep connection monitoring and socket-scoped timer disposal in lib/connection-health.js so reconnects do not accumulate background tasks.
- Never delete active Baileys authentication/encryption files during scheduled maintenance; only explicit logout may clear credentials.
- Maintenance expires bounded caches by retention policy, not process RSS, to preserve active conversations and anti-delete recovery.
- Load provider credentials through lib/env-config.js with a repository-relative .env path; keep Gemini chat, Gemini video analysis, image generation and YouTube search key pools separate so no service borrows another pool's credentials.
- Centralize Gemini authorization classification and bounded text requests in lib/keyserver.js; rejected credentials must not be retried across models, and Gemini/Hugging Face replies and logs must not expose raw provider errors because they can contain secrets.
- lib/voicechanger/env.js normalizes settings to prevent invalid numbers in provider requests.
- Bound every long-lived in-memory structure with a hard count cap in lib/maintenance.js (chat archive chats, learned style/facts people, connect chat list); unbounded growth over long uptimes caused host memory kills.
- Keep image generation in lib/image-generation.js with bounded requests, validated image buffers, and sanitized errors; V1 is evaluated with the repository-root require.
- Keep menu parsing, native button payloads, and chat-bound reply resolution in lib/menu-buttons.js; persist bounded expiring menu actions in the shared settings store and handle taps before command parsing in both engines so supplied text cannot execute commands.
- Keep fontpreview as a V2 command using the shared font registry and fontPlain replies; previews must never alter activation or restyle the chosen sample through the active font.
- lib/youtube-download.js owns downloads: preserve audio providers and bounded YouTube metadata; video title search uses relevant Dailymotion results, retaining public YouTube/Dailymotion links and ytmp4. Only approved canonical URLs; bound yt-dlp processes/files, never bypass access checks, relay validated media.
- Overlap audio download/upload with music-card delivery, but relay only after the card succeeds; hedge existing audio services with at most two fetches, cancel losers, and convert only the winner to avoid duplicate CPU/storage cost.
- Detect a second bot linked to the same number (fromMe notify replies/reactions to prefixed messages this socket did not send) in lib/v2/index.js and warn the owner at most every 6 hours; another device cannot be stopped from code.
- V2 has no dependencies of its own and resolves packages from the root node_modules; postinstall and startup remove v2/node_modules and in-folder npm caches (cache lives in /tmp via .npmrc) to keep hosting disk within budget.
- Startup removes a node_modules package found missing files (interrupted host install) plus npm's hidden lockfile, and a committed package-lock.json keeps host installs light; never delete credentials or data in this repair.
- Send bounded chatbot turns as Gemini contents, apart from personality prompts; restore DM archives, isolate group threads, serialize chat/sender delivery, and record only sent replies so answers retain their question.
- Both V2 menu paths include menuCommands and optional menuCategory without command ownership; shared conversions remain V1-only to prevent duplicate replies.
